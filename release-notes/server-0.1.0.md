# H-live Server 0.1.0

新增独立 Linux + Docker 服务端，使用 Rust + Salvo。服务器持续采集，网页负责控制与查看；关闭浏览器不会停止监控。桌面 0.3.0 继续保留，服务端镜像不会替换桌面 CDN 更新文件。

- 复用主播卡片、开播优先与人数排序、实时消息、场次总览、有效发言和在线统计、月度归档、删除预览及确认、CSV/XLSX 导出。
- 复用游客 HTTPS/WSS、原生签名、直连与代理分组、出口限速/退避及代理订阅维护。保持不使用抖音登录 Cookie、不新增礼物记录。
- 持久化目标任务，服务重启后恢复；手动停止或删除的任务保持停止，同一场次继续累计实际监控时长。
- 单管理员令牌、HttpOnly 会话、同源及 CSRF 防护、登录频率限制、请求体与并发上限；管理 API 仅暴露明确业务操作。
- 独立随机主密钥，用 XChaCha20-Poly1305 保护 Linux 代理与订阅配置；不回退明文，保留 Windows 桌面 DPAPI 兼容。
- 服务端管理导出目录，浏览器按随机任务 ID 下载，拒绝任意服务器路径；导出文件与记录保留七天。
- 非 root、只读根文件系统、独立数据卷和密钥卷、健康检查、SIGTERM 归档收尾、Docker 自动重启，以及 Linux 自身资源指标。

首次安装主播列表为空。桌面历史数据库可停机备份后迁移；Windows 加密代理需要重新导入。详见 `docs/server/README.md`。

300 个配置任务、约 50 个同时开播仍需按实际出口验证；尚未完成真实 50 房间及 24 小时生产验收。平台风控、游客下发范围和中断期间消息缺失仍然存在。

本项目仅用于学习研究，严禁用于商业谋利、破坏系统、盗取个人信息等行为。侵权或涉及相关利益请联系原作者。

## Podman 部署补充

新增 rootless Podman + Quadlet 单体部署包，复用 server 0.1.0 原镜像。一个容器承载网页、API、采集、SQLite 和导出，密钥在宿主机初始化，由 systemd 管理健康检查和自动重启。Linux 生命周期验收已通过；使用说明见 `docs/server/PODMAN.md`，证据见 `docs/engineering/SERVER_PODMAN_VALIDATION.md`。原 Docker 附件和桌面更新渠道保持不变。

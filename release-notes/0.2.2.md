# 氢看直播 0.2.2

本版新增按直播场次查看发言人数与有效互动分析，使用本地规则处理，不调用 AI，也不上传聊天内容。消息采集与分析分开进行，保留原始聊天记录。

## 直播场次与有效发言

- 点击主播卡片，在弹窗中查看该主播已登记的直播场次、累计监控时长、发言人数、有效发言人数和有效率。支持月份筛选、分页与当前场次优先。
- 以真实主播 ID 和真实场次 ID 归档。新登记的零消息场次也会展示。发言人数按发送人 ID 去重；昵称相同的不同账号分别统计，缺少 ID 的消息不虚构人数。
- 正常提问、回答、评论、感谢、反馈均可计入。一位观众只要有一条有效发言，就计入有效人数；其余刷屏消息不会抹去正常互动。
- 默认排除个人 60 秒内相同内容至少 3 条、60 秒内至少 20 条且来自 10 人的集中重复、整场至少 50 条且来自 20 人的重复内容。达到阈值时回溯排除对应分组，避免先收到的刷屏被计为有效。
- 匹配会统一全半角、大小写和多余空白，保留标点、否定词、数字与表情。数据库原文不修改。阈值可按主播调整，保存后后台重算。
- 明确提供参与口令和活动时间的活动信息可用于排除口令；证据不完整时保留「待判定」。支持手工确认本场口令后重算。重复规则优先，不将普通短句、负面评价或未核实活动条件直接视为无效。
- 可展开场次查看分类原因和消息样本，重新分析或暂停重算。分析结果带规则版本；统计未完成或存在待确认消息时，不显示确定的有效率。

## 分析导出与历史数据

- 新增场次分析 XLSX / CSV 导出，包含主播、场次、日期、监控时长、覆盖情况、聊天数、发言人数、有效人数、有效率、待判定数、清理标记与规则版本。
- 原始消息月度导出继续使用原有七列及多人分 Sheet 规则。
- 历史消息异步分析，进度写入本机数据库；重新打开后继续。重算、规则调整与删除记录不会修改原始消息内容。删除后旧分析结果失效，防止已删除数据重新出现。
- 监控中途开始、停止或更新造成的数据缺口不会补造消息；新场次标注「部分监控」，旧场次覆盖情况未知。人数与时长仅代表实际记录范围。

## 自动检查更新与监控恢复

- 默认启动后检查更新，此后每小时检查一次，可在设置关闭。发现版本时提示；不会自动下载安装。
- 监控运行时可选择「暂停监控并更新」。更新包下载及签名验证完成后，先原子保存正在运行的任务列表，再暂停连接、完成归档并启动安装。
- 更新完成重新打开后恢复这些任务；原本手动停止的任务保持停止。同一场次沿用已累计监控时长，更新暂停时间不计入。
- 下载或签名验证失败不暂停监控。安装启动失败时尝试在当前版本恢复；恢复文件只包含版本号和任务 ID，不包含 Cookie 或代理密码。
- 此恢复流程由本版加入，适用于从本版发起的后续更新。旧版本发起的本次升级仍遵循旧版本安装流程。

## 状态提示

- 将出口冷却与等待建连名额分别显示。名额限制的是建立连接的过程，已经正常连接的直播消息仍持续接收。

本地规则提供可核对的统计口径，不等于自动理解内容质量。阈值属于初始设置，可结合实际频道内容调整。

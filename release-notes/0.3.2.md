# 氢看直播 0.3.2

## 红包、福袋按活动轮次归档

- 修复同一个红包在预告、剩余份数变化、奖励和结束阶段反复保存、反复计数的问题。后续通知补充原活动详情，不再生成一轮新的活动。
- 红包与福袋保留各自统计。同一主播、同一场次内按活动标识合并；福袋继续兼容相同开奖时间的合并，并保留不同通知所使用的活动 ID 别名。
- 相同标题、钻石金额或红包份数不会被误当成同一轮，不把不同主播、不同场次的活动合并。
- 第一次打开旧消息库时，在事务中整理能可靠识别的历史重复活动，保留首次消息时间和身份，补全详情；失败或取消会回滚。
- 不再将缺少活动身份、详情的临时状态包保存为新活动。其他缺少可靠身份的通知保留证据，不凭文案猜轮数；统计不完整时显示已知数量下限或未知值。
- 领取奖励不代表整场红包已领完。显式结束、开奖结果或剩余份数归零会终止该活动，迟到的预告不会将其重新打开。

## 更简洁的监控卡片

- 移除占位主播头像。已确认正在进行的红包、福袋分别在主播名字前显示图标；没有确认当前活动时不显示灰色占位图标。
- 卡片中部固定为“当前在线、本场红包、本场福袋”三项，数值居中、竖线分隔，通过字号和颜色区分信息。较大的在线人数使用万、亿单位。
- 直播状态放在右上角，累计监控时间放在“开播中”右边；圆点与文字按两种内置字体校准对齐。
- 计时数字变化时增加轻微翻页效果，只动画发生变化的数位；初次显示和虚拟滚动恢复时直接显示正确时间。开启系统“减少动态效果”后直接更新。
- 底部左侧为低强调的停止图标按钮，右侧保留明确的直播间入口，使用电脑默认浏览器打开。操作区上下留白一致。
- 保留整张卡片打开详情、批量选择时显示复选框、未开播折叠，以及开播优先、在线人数倒序和无限滚动。

## 减少启动时的重复请求

- 同一出口启动多个监控任务时，合并游客首页请求并短期复用内存中的游客会话；不同出口相互隔离。
- 出现 HTTP 429、444 或房间信息暂不可用时，重新获取相应游客会话；等待过程支持任务取消。
- 每个房间继续使用独立的 WSS 消息连接，出口并发、请求间隔和冷却限制保留。
- 一个出口、12 个房间的相同合成测试中，游客首页请求由 12 次降到 1 次，连接准备耗时约从 17.6 秒降到 12.0 秒。该结果用于比较内部开销，不代表真实抖音网络下的速度保证。

## 更新与数据兼容

- 保留现有主播配置、历史聊天、有效发言分析、在线统计、CSV/XLSX 月度导出和记录删除。
- 同一场次中断后恢复，继续累计已保存的监控时长，不计入停止期间。
- 沿用原更新公钥、用户数据目录和 CDN 更新地址；继续每小时检查更新，确认安装后暂停监控并在更新完成后恢复任务。
- 不引入抖音登录 Cookie，不新增礼物记录；原有历史礼物仍可导出。

## 统计与验证范围

- 卡片数量是本场监控已识别的活动轮数，不能补采开始监控前或断线期间的活动。缺少可靠结束时间时，不将通知直接当作当前仍在进行的活动。
- CSV 导出不包含原始活动 ID，不能仅凭重复文案准确恢复所有轮次；本次升级以消息库保留的协议身份为依据。
- 前端、归档、迁移、导出和采集回归已通过，包含 300 个配置任务、50 个合成消息连接及集中重连验证；不等于真实平台 50 房间或 24 小时连续运行保证。

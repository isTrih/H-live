# 氢看直播 0.2.4

## 游客监控与礼物功能

- 按当前游客批量监控需求，移除礼物采集与入库，礼物不再增加任务消息条数，也不显示在实时分类或“全部”中。
- 已存历史礼物记录保留；月度归档中的“礼物（历史）”仅用于导出旧数据。聊天、点赞、关注／分享、粉丝团、表情和红包／福袋继续处理，进入消息仍不显示在实时列表。
- 现场同一房间连续监听 20 分钟，聊天 26 条、活动 2 条、礼物原始包 0；网页 Origin 的八分钟对照也未收到礼物。该结论仅描述这次游客连接；没有测试登录态，也不把“不下发”说成“礼物协议不存在”。
- 原仓库与相关上游存在登录 Cookie 成功案例及后续失效反馈，未找到能验证适合当前游客大批量场景的稳定方案。本版不再为礼物重写采集层或引入登录依赖。

## 福袋合并

- 同一主播、同一真实场次、同一开奖时间的福袋通知合并为一条记录，消息 ID 不同也不会重复入库或增加实时消息条数。开奖时间统一按完整日期的秒数比较，秒／毫秒格式一致处理。
- 后续通知补充奖品和参与条件时更新原记录；空值不覆盖已知详情，参与条件去重保留，并继续用于活动口令识别。红包、不同主播／场次／开奖时间保持独立；没有可靠开奖时间时不猜测合并。
- 首次打开旧消息库时，在同一事务中合并符合条件的历史福袋重复通知，保留最早一条的消息身份和时间；普通聊天、礼物、红包及场次在线统计不受影响。失败或取消时整体回滚。

## 刷新在线人数

- 看板顶部新增「刷新人数」，主动查询正在监控的开播直播间。刷新期间显示进度并禁止重复提交，完成后提示成功、失败数量。
- 使用每个任务现有的直连或代理出口及登录凭据，最多四个刷新请求任务并行，并遵循出口原有 HTTP 限速和冷却。连续点击不会建立重复批次，十秒内不重新提交。
- 不重连正常 WSS。刷新过程中收到更新的 WSS 人数时，保留较新数据；已停止任务、已变化场次或失败请求不会覆盖旧人数，也不会自动把主播标为下播。HTTP 444 / 429 继续触发对应出口冷却。

## 场次在线统计

- 明确显示「有效发言占比」＝有效发言人数 ÷ 总发言人数，二者均按本场账号 ID 去重。与「有效／在线」分开显示；分母为零或分析未完成时显示「—」。场次分析导出中的对应列同步命名为「有效发言占比」。
- 场次总览增加「最高在线」「分钟均在线」「有效发言／在线」。
- 最高在线取监控期间实际收到的有效在线人数峰值。在线数据单独按真实主播与真实场次保存，不混入聊天消息、聊天条数或运行日志。
- 分钟均在线先计算每个分钟内有效采样的平均人数，再对已采样分钟等权平均，避免消息更密集的分钟占过大权重。缺失分钟和停止监控的间隔不补零、不延续最后人数。
- 同场次暂停、重启后继续累计；新真实场次单独统计。历史没有采样的场次显示「—」。真实零人数与未取得数据分别处理。
- 默认有效发言／在线＝整场按账号 ID 去重的有效发言人数 ÷ 分钟均在线；分析尚未完成或均在线为零时不显示确定百分比。该比值可能超过 100%，因为累计有效发言人数与同时在线人数的统计范围不同。
- 表头说明统计口径，均在线数值提示已采样分钟数。统计只代表实际监控覆盖范围，不代表整场直播的完整在线数据。

## 导出与兼容

- 场次分析 CSV / XLSX 在原 14 列后追加最高在线人数、分钟平均在线人数、有效发言／平均在线、在线采样分钟数，缺少数据留空。
- 原始聊天月度导出继续使用原七列。删除聊天记录不删除独立在线统计，发言人数随清理重算；清理过聊天的场次不再显示在线占比，避免分子与在线采样覆盖范围不一致。
- schema v3 追加独立采样表，保留消息、场次、时长与既有分析。沿用原安装及签名更新渠道，不改动历史发行文件。
- 沿用 0.2.3 的互动显示修复；本版没有新增礼物下发完整性的承诺。
- 本次为同版本修订，版本号保持 0.2.4。已经安装 0.2.4 的客户端需手动覆盖安装新包；Tauri 更新检查不会将相同版本判定为更新。

# 氢看直播 0.2.0

本版将消息解码、内容归档和月度导出迁入 Rust，整理源码与构建入口。已有主播、代理配置和聊天归档继续使用。

## 更快的消息处理和导出

- gzip / protobuf 消息解码由 Rust 处理，保留聊天、礼物、点赞、进场、关注/分享、粉丝团和表情消息，继续保留真实场次、昵称、长 ID 和服务端时间。
- SQLite 归档使用有界队列、批量事务和缓存语句。返回写入成功前等待事务提交；关闭和更新会等待归档完成。
- CSV 与 XLSX 改由 Rust 流式导出。多主播按名字分工作表，单主播文件名继续包含主播名；固定七列包含「发消息人名字」。
- 保留长 ID 文本、公式保护、重名工作表、超行续表、北京时间月份和缺失值规则。取消或导出失败保留原目标文件。
- 本机相同 60,000 条消息 / 300 位主播：CSV 从 3.090 秒降至 1.008 秒，XLSX 从 5.089 秒降至 1.525 秒。300 个模拟生产者在 3,000 条/秒负载下全部提交；更高突发仍会排队。完整方法与限制见工程性能报告。

## 更清晰的代码与生命周期

- 独立 `qingkan-core` 保存协议、归档和导出实现，`qingkan-native` 提供同进程 Python 适配；解码及磁盘工作释放 GIL。
- Tauri 拆分窗口、后台命令、进程管理与更新策略；前端提取主播筛选、状态和时长规则。
- 当前界面、采集代码、原生模块、测试、文档与历史实现分别归档。旧 Tk 界面及 Inno 安装配置不再进入正式构建。
- 收到直播结束通知后，即使消费回调异常，也会关闭该场连接。
- 原生模块和后台版本不匹配时明确报错；安装版自检验证实际加载的 Rust 模块，避免静默使用旧实现。

## 更轻的界面外壳

- 外层 5 px 边框改为 5% 灰色（#F2F2F2），内层、顶部菜单和底部状态栏使用纯白。
- 主播卡片继续用绿色、灰色及异常状态色区分当前状态。

## 升级和兼容

- 版本统一为 **0.2.0**，沿用原安装身份、用户数据目录和数据库结构。Cookie 与导入代理凭据仍由当前 Windows 用户 DPAPI 加密。
- 保留原更新公钥与更新清单地址：`https://assets.checkpoint321.com/lilith/qingkan-live/latest.json`。
- 安装版自带采集运行环境，无需另装 Python、Rust、Node.js 或 Excel。HTTP / WebSocket、签名、代理池和任务调度仍使用 Python；本版不是全 Rust 重写。
- 0.1.0 / 0.1.1 历史发行文件保留。维护者上传新的安装包、签名和更新清单到 CDN 后，旧版「检查更新」才能发现本版。

性能数字来自本机合成数据，不代表 300 路真实平台连接能力。代理可用率、平台登录限制及消息完整性仍受网络和平台影响。本版具体回归、安装与隔离升级验收见随包评估记录。

# 直播详情：互动回放与场次卡片

设计目标：回放与时间轴成为主区域，场次像剧集一样选择；主播身份只显示一次。沿用现有灰白、浅绿桌面界面，没有增加头像和品牌素材。

## 本次调整

- 删除重复主播标题、详情和列表头像；在线与监控时长合并为一行。
- 黑色画面承载归档聊天弹幕，支持暂停、拖动、倍速和回到最新；这是聊天回放，没有接入视频流。
- 时间轴面积图按真实消息数量分桶，缺失时间的聊天单独提示，不编造定位。
- 场次默认显示六张卡片，点击切换；悬停或键盘聚焦显示统计小卡。浮层挂在页面顶层并限制在视口内，避免被弹窗滚动容器裁切。
- 日期使用上海时区的 `YY/MM/DD`，如 `26/10/25`；标题和浮层需要时附时分。
- 亮点配置入口关闭详情、跳转全局设置页。API 地址、上游模型和加密保存的 Key 供所有主播共用。
- 手动分析读取同场全部可用归档、活动、在线采样和状态，使用一次完整 prompt 请求；不截断、不分批、不自动重试付费请求。上下文不足时显示明确错误。亮点必须引用本场不同已知发言账号的可核验聊天证据。

## 动效与状态

复用弹窗和标签页过渡，新增弹幕移动、进度游标、悬浮卡出现及分析等待反馈。遵循系统减少动态效果设置。切场、关闭详情时清理回放与分析任务；定时刷新保留播放位置、卡片焦点及手动选中的历史场次。真实开播切场时当前卡片和播放器同步跟随。

## 验证

- `./scripts/test.ps1 -Suite frontend`：85 项通过。
- 时间轴、设置、场次选择等相关异步测试在开发过程多次通过，覆盖迟到响应、关闭、切场、配置保存失败和模型任务读取失败。
- Rust 定向测试通过：完整归档时间轴 3 项；AI Runtime 9 项；服务端鉴权/加密配置及慢模型获取不阻塞停止监控测试 2 项。Runtime 与 Server 编译检查通过。
- 模拟上游验证单次 completion、单个 prompt，保留全部 203 条记录、长消息、事件 payload、在线信息和统计；未使用真实第三方 API Key 实测上游模型。
- 在应用内浏览器手动走通设置跳转、获取模型、保存、返回详情、分析、点击灯泡、历史场次切换、弹幕与进度操作。

## 独立检查与取舍

进行一轮独立代码审阅，修复跨场选择不同步、卡片焦点丢失、浮层裁切、配置加载覆盖输入，以及模型获取阻塞停止监控的问题。进行一轮存量界面视觉评审，不打分：缩小悬浮卡、合并指标、删除重复场次数量和预览说明；保留当前模型名称，便于确认本场实际使用的模型。

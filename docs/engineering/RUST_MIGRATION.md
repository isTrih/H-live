# 纯 Rust 后端迁移计划

2026-10-16。当前可构建基线：0.2.4（Tauri + Rust 核心 + Python 采集）。以下均为待实现或待验收项目，不能据此宣称已完成迁移。

## 保持的契约

保留 UI、现有数据库 schema 与升级路径、主播真实场次隔离、停顿不计时、分钟在线统计、本地发言质量规则、月导出、归档删除、更新暂停与恢复。礼物只保留历史查询/导出，不新增采集；不使用登录 Cookie，不播放/录制直播流。

## 模块与次序

1. 原生签名：从同一个类型化参数对象构建 WSS query 与 13 字段规范串，移植 Remastered 的 MD5/RC4/Base64 兼容变换；保留上游 MIT 署名。先通过五组上游向量，再增加非零随机输入和全链兼容测试。不得复制固定 did、旧时间与 cursor。
2. 网络与出口：Tokio + 经校验的 TLS HTTP/WSS，按出口共享客户端、请求速率、建连名额和冷却。直连算一个出口；HTTP CONNECT 与“HTTPS 目标可用”分清，不默认给普通代理端口套第二层 TLS。
3. 生命周期：任务具有代次及取消 token，重新启动不能接受旧回调。心跳使用异步定时，不为每个房间创建线程。停止等待退出确认，订阅移除后已有租约完成清理。
4. 数据与界面：复用 `qingkan-core`；数据库和导出走有界后台工作队列，不能阻塞 UI/网络运行时。界面按批读取有限快照；显示缓存淘汰与归档丢失分别计量。
5. 配置与安全：保留原数据目录兼容；配置原子写入；认证代理凭据按用户加密并在日志中脱敏。删除登录入口，旧登录字段不参与网络请求；不静默删除历史数据。
6. 发行：移除 Python sidecar、PyO3 适配与 MiniRacer/V8、JS 签名 SDK。打包与许可证按实际依赖重新生成，原更新私钥不进入源码或 CI。

## 验收门槛

- 单房真实游客 WSS 连接、ACK/心跳、聊天与在线事件；平台没有下发的事件不伪造为成功。
- 使用隔离合成数据完成旧库升级、同开奖福袋合并、场次续时、导出及删除契约验证。
- 离线模拟 300 个配置任务、50 条并发连接和重连洪峰，记录 CPU、内存、线程、队列、丢弃、停止耗时。此测试不等于平台真实 50 房并发验收。
- 真实网络小规模渐增观察，与旧版本相同条件比较；遇 429/444 按出口退避，不能承诺 Rust 本身避免限流。
- 出口 HTTP CONNECT / SOCKS、认证失败、TLS 失败、订阅过期、取消、断网、超限帧及解压炸弹验证。
- 安装器与更新签名验证，更新暂停与恢复；真实用户安装和数据库不作为破坏性测试目标。
- 发行包无 Python、Node、V8 或外部签名服务依赖后，才可标为纯 Rust 后端正式版。

## 上游取舍

原项目用于理解已知协议与业务行为；Remastered 用于原生签名实现参考。不会直接引入其播放器、抓流、登录和 Win32 UI；其单房选择逻辑及一房一心跳线程不适合本项目目标。完整源码比较与固定提交链接见 [调研报告](../research/remastered-rust-migration-2026-10-16.md)。

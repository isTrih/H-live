# 离线查询调度与界面性能 · 2026-10-19

本次改动共用同一套 Rust 运行时，适用于 Tauri 桌面和 Salvo 服务端，随桌面 0.3.1 与服务端 0.1.1 发布。已有 0.3.0 安装包及 server-v0.1.0 镜像保持不变。

## 状态查询策略

平台明确返回未开播时才增加离线计数。首次等待 **30 秒**，连续确认后依次为 **60、120、240、480、600 秒**，以后保持 600 秒。确认开播或重新开始任务时重置。HTTP 444、请求失败、状态待确认不算未开播，继续执行原有错误退避和出口冷却。

已连接 WSS 持续接收消息，心跳、归档、在线统计和重连不随聊天活跃度降频；不能用“没有消息”推断下播。

到期查询进入最多同时执行 8 次的优先队列，次序为：已知直播的断线重连、常播时间段任务、新任务、连续未播任务。连续未播次数越多优先级越低；等待满 60 秒提升到最高优先级，同级按入队顺序处理。协调器只唤醒获选任务，查询名额在取得房间信息后释放，不被长连接占用。原有每出口请求节奏、建连限制、失败冷却和代理生命周期继续生效，手动刷新在线人数也保留原出口限制。

30–600 秒是再次进入队列前的等待，排队、出口冷却及网络请求还会增加实际检测延迟。非常播时间的新直播可能约 10 分钟甚至更久才发现；常播窗口缩短为 30 秒，不保证 30 秒内成功连接。

## 内部开播偏好

不使用 AI、不增加外部请求。确认直播以及连接期间每 5 秒的现有检查点观察当前时间，记录实际开播的半小时桶；同一天同一桶不反复修改缓存。使用北京时间 UTC+8 的日内时段，暂不细分星期。

近 28 天观测到的桶及相邻半小时桶视为常播窗口。窗口内恢复 30 秒查询并提权；较长等待会越过窗口边界时，提前到边界检查。只学习升级后实际观测的时段，**不把旧场次首末消息之间推断成持续开播**，也不反推未监控期间的行为。

按真实主播 ID 保存，入口 ID 作为别名；识别到同一主播的新入口后共享习惯。未识别身份的新入口没有偏好。缓存为数据目录 `polling-habits.json`，每 5 秒仅在有修改时原子保存，退出及更新准备时再保存；服务端随数据卷持久化，不修改消息库结构。读取上限 4 MiB、最多 10000 个主播及入口、每主播最多 48 桶；未来格式或损坏缓存不覆盖，也不阻止采集。保存失败只记日志，原始消息继续归档。

## 界面设计

北极星：看在线状态和人数 → 查看场次指标 → 核查样本 → 导出。诊断和设置不挤占阅读区。保留顶部导航、两种本地字体、绿色开播宫格、灰色未播折叠组、白色内容与轻圆角。当前卡片 172px 高、间距 18px。

详情分为“场次分析 / 连接信息 / 主播设置”，底部固定开始停止操作，移除任务放在设置。查看样本时固定标题显示主播名和所选日期；月份和导出同组，全部重新分析移进折叠规则区。页签支持方向键、Home/End，切换保留名称草稿，关闭回到原触发控件。小窗口减少表格可见行数，正文和样本仍有界滚动。

月度归档以选择与导出为主体，导出记录旁置，字段定义折叠。代理页先给配置和出口负载，任务分配折叠、搜索后每页最多 50 条。设置改成单列。不增加装饰图片、远程字体或动效依赖。

常规管理轮询不再构建完整代理快照，代理页独立每 3 秒取一次。未变化的统计、代理列表、消息、日志和导出记录保留 DOM。页面后台或最小化时暂停定时界面请求，回前台立即拉取，Rust 采集持续运行。模态遮罩取消背景模糊，保留短反馈并尊重减少动态效果。

## 验证与性能边界

Windows 本机开发构建、合成传输，不连接真实抖音房间；经过实际运行时、解析、归档、质量统计和出口准入。不含 WebView 或完整 HTTP 服务内存，不是 24 小时容量保证。

| 检查 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 300 任务、1000 候选的常规轮询 JSON | 257792 字节 | 80751 字节 |
| 同进程 100 次管理轮询 | 3828ms（完整快照） | 1236ms（精简快照） |
| 代理分配列表行数 | 300 | 50 |
| 静止列表 3.2 秒内重建 | 4 次 | 0 次，保留首行节点 |
| 同场景页面元素 | 2569 | 578 |
| 300 任务、50 合成直播建立至 50 连接 | 6.21s | 4.11s |
| 同上停止任务 | 0.080s | 0.104s |
| 同上采集进程观测峰值 RSS | 32.2MiB | 31.5MiB |
| 同上平均单核 CPU 占比 | 26.9% | 32.8% |

精简轮询约减少 69% 响应体和 68% 此项耗时。CPU 本轮没有下降，不能声称整体采集 CPU 降低；短时开发构建的时序与调度开销需长时间实机复核。50 个连接均经历一次强制断线并恢复，归档 3032 条合成聊天、0 条新增礼物、0 个失败写入批次，退出后连接和工作任务全部结束。长期未播且不在常播窗口的任务，理论状态查询频率由每分钟一次降为每 10 分钟一次，实际效果取决于开播分布及出口条件。

回归覆盖离线间隔、窗口边界/跨午夜/过期、优先级与等待提升、取消释放名额、跨重启缓存、重开任务重置计数、精简轮询兼容，以及既有 SQLite 迁移、删除、累计时长、有效发言和 CSV/XLSX 导出。浏览器以 1440×900、1280×800、双倍像素密度检查八种状态，无页面异常及横向溢出；页签键盘、草稿保留、任务分页、减少动态效果通过。独立存量界面评审一轮、不打分，按意见压缩详情头部并固定样本上下文。

# 代理可用性诊断

日期：2026-10-14，时间均为北京时间。范围：当前 v2 的 HTTPS 初检、房间接口、真实消息连接，以及独立 TLS 对照。本文 700 候选结论针对原 scdn 来源；稍后新增来源的成功联测见 [三个代理来源评估](PROXY_SOURCES_REVIEW.md)。

## 结论

检测有展示与判定上的不足，已修正；但本次低可用率不是仅由这些问题造成。针对 scdn 两轮共检查 **700 个不同候选**，4 个曾通过首页检查，**0 个通过同代理房间接口，该来源的这批样本未找到能收取真实消息的代理**。样本不代表来源中的全部地址都不可用，也不证明以后仍会如此。随后另测 ProxyHub 与 ProxyClean 已找到收到真实互动内容的公网代理，未将这些结果计入 scdn 或自动切换应用来源。

当前接收代码在直连和临时本机 CONNECT 转发下均成功收到真实内容。后者的出口仍是本机，只证明 HTTP/WS 代理传输路径能工作，不能作为公共池成功、出口隔离或 300 路容量的证据。

## 检测方式核查

- 来源始终使用 `protocol=https`。`http://IP:port` 表示先建立 HTTP CONNECT 隧道，随后在隧道内与抖音进行严格校验的 TLS 连接；不是明文发送抖音内容。`https://IP:port` 则还要求先与代理本身建立 TLS。不能仅凭来源标签统一修改 URL scheme；6 个样本的 scheme 对照没有恢复成功。[urllib3 官方说明](https://urllib3.readthedocs.io/en/stable/advanced-usage.html#http-and-https-proxies)，[来源 API 文档](https://proxy.scdn.io/api_docs.php)。
- 原初检仅获取首页响应头，曾把 200–399 都记作通过。它不能证明完整页面、房间接口或 WebSocket 可达；其中两个代理虽然完整首页也返回 200，后续房间接口仍超时。
- 6 个样本中，原生 socket CONNECT 有 5 个返回 200；随后 4 个在严格 TLS 中出现 EOF，另 1 个证书验证失败。EOF 意味连接提前关闭，不能仅据此确定是代理、链路中间设备还是目标端主动关闭。
- `3.26.199.107:8123` 的严格 OpenSSL 握手取得 `CN=live.douyin.com`、签发者 `CN=ADFS Signing` 的不受信任证书；同期直连是正常的 `*.douyin.com` → RapidSSL → DigiCert 链。Windows curl/Schannel 也拒绝该代理证书，不支持将其简单归因于 Python 的 CA 库。
- Windows curl 对两个此前 EOF 样本分别使用默认 TLS、仅 TLS 1.2，并保持证书验证，四次均未成功。诊断没有关闭校验或信任额外 CA。
- 已尝试放宽超时；两个首页可达的代理，其房间 enter 请求仍在 20 秒超时。新 Session / `Connection: close` 对照在首页就出现 502 或证书错误，未能进入相同接口阶段，故尚不能确定连接复用是否相关。

## 真实结果

| 路径 | 样本 / 条件 | 结果 |
| --- | --- | --- |
| 公共 HTTPS 源第一轮 | 300 个不同地址；首页采用生产 `(3,5)` 超时 | 3 个首页 HTTP 200；同代理生产房间查询均失败 |
| 公共 HTTPS 源第二轮 | 排除上述地址，新增 400 个；首页 `(5,10)`；350 个不限国家、50 个 CN | 仅 1 个首页 HTTP 200；房间查询超时；50 个 CN 均未通过首页 |
| 直连正对照 | 房间 `145926919737`，22:01:20–22:02:05，45 秒 | 109 条内容：89 点赞、16 进入、2 弹幕、2 社交 |
| 本机 CONNECT 正对照 | 同房间，22:14:49–22:15:34，45 秒；固定本机临时代理 | 41 条内容：24 点赞、12 进入、3 弹幕、2 社交；确证 WS socket 连接本机代理 |

两个正对照的归档、回调及计数一致，停止后无新增。所有对照未使用用户登录 Cookie，仅使用平台匿名访客凭据；没有音视频播放或录制，没有修改用户任务。用户原先提供的三个房间在本次检查时均下播，因此使用公开正在直播的房间临时验证。

本机对照通过诊断工厂参数把固定代理传给生产房间查询与消息 Fetcher，绕过公共候选获取；并非完整公共池租约验收。仅监听 `127.0.0.1` 随机端口、限定两个抖音主机的 CONNECT，不解密 TLS。共有 3 条 HTTP 隧道、1 条 WS 隧道；WS 上行 14,767 字节、下行 103,289 字节，TLSv1.3。结束后监听、连接和线程均清理，没有修改系统代理。

另从来源网页列出的 HTTP 类型地址取 10 个做独立对照，均未通过 HTTPS 初检；它们不计入上述 700 个 HTTPS API 候选。各批次超时设置与来源筛选不同，不合并推算来源整体可用率。

## 已做的改进

1. 初检仅接受 HTTP 200；重定向不再进入可分配池。
2. 界面「可用」改为「首页通过」，表示初检通过、未分配且未过期的候选；状态栏使用「待分配」。开始任务后才会继续同代理房间接口与消息连接。
3. 原「代理 TLS 握手被提前关闭」改为「经代理访问目标站点时，TLS 连接被提前关闭」，避免错误归因；证书与协议错误分别提示。

定向代理池测试 21 项通过，含重定向拒绝；前端语法检查通过。没有因本次样本而自动切换来源、改变系统代理、关闭 TLS 校验、放宽生产超时或恢复已失败候选。当前内置 scdn 来源的真实消息能力仍未验收通过；其他来源固定地址的成功证据见新增评估。

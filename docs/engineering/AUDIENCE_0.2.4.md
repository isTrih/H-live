# 0.2.4 在线采样与手动刷新

在线人数来自现有直播间元数据和 WSS stats，不发起额外定时 HTTP 轮询。有效值必须为非负安全整数，按当前任务绑定的真实主播、场次校验，旧连接、停止回调与串场数据不写入。

`audience_minutes` 独立保存每分钟采样均值、样本数、最新采样时间和峰值，主键为主播 / 场次 / 分钟。分钟使用接收时间对应的 UTC 分钟；上海时区分钟边界相同。迟到或重复时间不重复累加均值，峰值仍保留实际观察值。均值使用递推运算，避免累计大整数和溢出。页面均在线对每个已采样分钟的均值等权平均；它不是完整直播、连续时间加权平均，也不填补监控缺口。

最高在线为已有分钟峰值的最大值；无采样返回 null，有效零值返回 0。历史没有数据则不计算百分比。场次有效发言人数为整场有效发言账号去重，发言／均在线可以超过 100%；分析未完成、待判定或分母为零时保留未知。原有效发言率仍为有效发言人数 / 发言人数，两项分开显示。

采样通过 Rust 原有 mutation gate 和短事务写入，不作为聊天事件广播、不增加聊天计数。数据库写失败仅发一次明确运行告警，当前人数仍更新，不补造缺失数据。停止与采样共用单房 write_lock，采样 I/O 不持有全局 manager 锁。同场恢复共用同一场次桶，新场不串用。清理聊天保留独立在线采样，聊天分析及占比随清理重算。

手动刷新使用单个协调线程和最多四个工作线程，队列上限为已有任务数（应用最多 300 个）。沿用任务的 Cookie、出口租约、RouteControl 与停止信号，不另建 WSS、不临时转直连。批次 ID、进度和终态通过现有 poll 的 metrics 传输；前端忽略旧批次或倒退进度，避免重复提交与重复完成通知。无任务批次不联网。

刷新 HTTP 返回后必须仍是同一个任务实例、连接 attempt 和真实场次；请求过程中出现更新 WSS 人数时，revision 检查丢弃旧结果。HTTP 444 / 429 冷却原出口，不据此关闭现有健康连接或推断下播。失败保留原数值，并汇总失败数。

schema 保持 v3，追加独立表；旧版仍能读取已有内容结构。新增统计只放入场次分析导出的末四列，原始消息七列不变。验证包括真实 Rust 归档、50 个模拟房间并发刷新、更新覆盖竞态、停止及串场拒绝、缺失/零值、CSV/XLSX 和独立安装升级；模拟刷新不代表平台一定允许 50 个房间同时 HTTP 请求。

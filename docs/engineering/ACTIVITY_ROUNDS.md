# 活动轮次与紧凑监控卡片

2026-10-19 开发验证；基于桌面 0.3.1 / 服务端 0.1.1，本文不是新的安装包发布记录。

## 统计口径

同一活动的预告、剩余份数变化、奖励和结束通知合并为一条归档记录。红包和福袋仍是独立类型，卡片分别显示本场累计发现的轮数，不把通知条数当作活动次数，也不把红包份数当作轮数。

- 活动标识按真实主播、场次、类型隔离，长 ID 保持字符串。
- 福袋沿用相同开奖秒合并规则，兼容秒和毫秒；已建立的其他活动 ID 作为别名保留，后续结果通知仍能找到原记录。
- 红包按活动 ID 合并，不使用相同标题、金额、份数或 campaign ID 猜测同一轮。
- 缺少 ID 且没有可靠福袋开奖时间的通知保留原始证据，不编造轮数。存在这类通知时，已知数量以 `≥N` 显示；没有任何可识别轮次时显示 `—`。
- 仅 Common 字段的临时红包状态包不提供活动身份和详情，采集端不再将其当作新的活动消息保存；既有历史记录仍保留。

首次打开旧库时，在现有升级事务内逐页整理有可靠标识的活动记录，保留最早消息的 ID 和时间信封，合并详情后删除冗余通知。升级失败或取消时回滚；其他聊天、发言人、导出七列和监控时长不改写。活动别名及统计投影随对应消息删除，不留下旧的去重键。

红包奖励消息不等于全部领完；显式结束通知、开奖结果或剩余份数为零才终止该轮。终止状态不会被迟到的预告重新打开。已知结束时间过后，卡片会自动隐藏图标，不必再收到一条结束通知。

## 卡片与运行时

卡片不再使用占位头像。名字前只显示已确认仍有活动的红包/福袋图像；活动缺少可靠结束时间、连接中断或任务停止时，不显示代表当前活动的图标。灰度图标已取消。数量表示本场监控所发现的活动，不保证覆盖开始监控之前的活动。

名字在左，直播状态和累计监控时间在右上并排显示，时间位于“开播中”右边；中部为居中数值的当前在线、本场红包、本场福袋，两条竖线区分指标。大在线数使用万/亿单位，完整数值仍留在可访问标签中。底部左侧为低强调停止图标、右侧为带文字的直播间入口。底部高度 45px，按钮上下各 8px；卡片高 158px，继续使用有界虚拟滚动和批量选择模式。

计时使用 240ms 的数字翻页效果，只更新变化的数位，不翻动整张卡片。沿用既有看板更新节奏，没有为每张卡另开计时器。初次出现、虚拟滚动重新挂载、时长位数增长和未知值恢复时直接显示正确时间；系统“减少动态效果”开启后直接更新。浏览器检查覆盖秒/分钟进位、超过 99 小时、停止后隐藏、动画节点清理和两种字体的常规/双倍密度排布。

活动汇总在场次连接时读取一次，收到活动后合并刷新，连续消息下至多每秒读取一次；静默连接通过五秒检查点处理尚未刷新的变更。看板的一秒轮询不重新扫描历史消息。没有新增活动 HTTP 轮询、登录 Cookie 或礼物采集。

同一出口的游客首页请求合并，并在内存中复用十分钟；出口之间隔离，代理更换不会继承旧 Route 的缓存。429/444 或房间暂不可用时清除对应缓存；停止任务可取消等待。每个房间仍有独立 WSS，原有出口并发、间隔和冷却限制保留。运行中的既有连接不因缓存到期被中断。

## 验证

- 前端 60 项测试；Rust 工作区 141 项测试；桌面和服务端网页构建及 Tauri 编译检查通过。
- 新回归覆盖：红包生命周期、相同文案的不同红包、跨主播/场次/类型隔离、福袋 ID 与开奖时间连接、历史归并、重启和删除、未知身份、游客缓存隔离/到期/取消、协议到卡片汇总的真实生产代码路径。
- 浏览器检查覆盖 1440×900、1280×800、双倍像素密度、两种字体、减少动态效果、停止/开始、整卡弹窗、批量选择、未播折叠及虚拟滚动、到期隐藏图标。字形测量中圆点与状态文字可见中心相同，底部按钮上下留白均为 8px。
- 相同合成传输、一个出口及原有速率限制下，12 房间首页请求从 12 次降到 1 次，连接准备约 17.56 秒降到 12.04 秒（约 31%）。这是内部开销对比，不是抖音现场承诺。
- 300 任务、50 合成消息连接及一次集中重连通过：3,127 条聊天、0 条新礼物、0 个归档失败批次；退出后所有连接和工作任务关闭。本机 Windows 开发构建观测峰值 RSS 约 33.1 MiB，不含完整桌面 WebView，也不是服务器或真实房间的容量保证。

用户提供的 CSV 仅含导出七列，没有活动 ID 和原始协议载荷。可以观察到重复的生命周期文案，但不能由该 CSV 准确恢复所有活动轮次；原文件未修改，真实用户数据未加入测试夹具或公开仓库。本次没有声称完成真实房间的活动全量接收验收。

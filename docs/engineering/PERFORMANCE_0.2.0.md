# 0.2.0 本机性能验证

2026-10-15，在当前 Windows 10 x64、16 逻辑处理器、CPython 3.12.14 环境执行。比较对象为冻结的 0.1.1 Python 实现与 0.2.0 release Rust 扩展，包含实际 Python 适配和 JSON 转换成本。所有数据为合成消息，真实网络连接数为 0。

原生扩展 SHA-256：`de7cda7a71063bca9e79cd5f6e0e08cf8ee40f498faf68c48f95f2a3c7006e3d`。

## 固定数据导出

相同 60,000 条内容、300 位主播，关闭写入后分别导出。每种实现使用独立进程；CSV 的规范化行、XLSX 的工作表及单元格值进行 SHA-256 对照，均一致。XLSX 生成 300 个主播工作表，包含昵称和长 ID。

| 操作 | 0.1.1 Python | 0.2.0 Rust | 本轮结果 |
| --- | ---: | ---: | ---: |
| CSV 60,000 行 | 3.090 秒 | 1.008 秒 | 约 3.06 倍速度 |
| XLSX 60,000 行 / 300 表 | 5.089 秒 | 1.525 秒 | 约 3.34 倍速度 |

这里是同一次本机比较，不是所有数据规模的保证。并发导出阶段快照行数不同，不用于计算导出倍率。导出后验证工具会再次读取文件，因此进程累计内存峰值不能单独归因于导出器。

## 300 个生产者并发归档

使用 300 个 Python 生产者线程，调用正式适配器并等待 SQLite 事务提交；期间另有 CSV 导出。默认队列 4096、批次上限 256、聚合等待 4 ms，两个版本参数一致。

| 负载 | Python | Rust | 数据完整性 |
| --- | --- | --- | --- |
| 目标 3,000 条/秒、10 秒 | 30,000 条 / 9.999 秒 | 30,000 条 / 9.956 秒 | 两版全部提交 |
| 目标 6,000 条/秒、5 秒突发 | 30,000 条 / 8.318 秒，约 3,607 条/秒 | 30,000 条 / 6.642 秒，约 4,516 条/秒 | 两版最终排空，无丢失 |
| 3,000 条/秒阶段提交 P95 | 71.83 ms | 58.32 ms | 统计从调用到提交确认 |
| 突发阶段提交 P95 | 137.59 ms | 112.22 ms | 包含排队等待 |
| 归档阶段进程累计峰值工作集 | 46.45 MiB | 50.44 MiB | Rust 本轮内存没有下降 |

每个版本最终数据库均为 60,000 条，`integrity_check=ok`，关闭后待写数和队列深度为 0。两版均未达到持续 6,000 条/秒，不能把突发排空结果描述为可持续吞吐。

## 协议解码

通过正式 `_wsOnMessage` 入口处理相同 gzip / protobuf 帧，每帧 70 条、覆盖 7 类内容，200 帧共 14,000 条；包括 ACK 生成、原生 JSON 返回、Python 解析与回调投递。每轮新进程，交替运行顺序，共 3 轮，先做少量预热。事件及 ACK 哈希完全一致。

| 项目 | Python | Rust |
| --- | ---: | ---: |
| 3 轮耗时中位数 | 17.466 秒 | 0.1258 秒 |
| 耗时范围 | 14.542–21.632 秒 | 0.1134–0.1429 秒 |
| 中位数速度比 | 1 | 约 138.8 |

这是重复合成帧的局部微基准，系统同时存在其他开发工作，耗时范围体现了调度波动。它表明解码热点有明显改善，**不能解释为整个应用快 139 倍**。不包含 TLS、HTTP/WSS 收包、V8 签名、数据库写入、代理或 WebView。

## 优化过程与复现

首轮原生实现曾慢于 Python：SQLite 每条记录重新准备语句，XLSX 对压缩器产生过多小写入。实际测量后改为缓存 SQL 语句与按行缓冲输出，再运行相同验证；没有只依据语言选择推断性能。

```powershell
.\scripts\build_native.ps1
.\.venv\Scripts\python.exe scripts/benchmarks/benchmark_protocol_native.py
.\.venv\Scripts\python.exe scripts/diagnostics/benchmark_native_archive.py
```

输出记录：

- `build/benchmark-0.2.0/protocol.json`：逐轮时间、事件/ACK 哈希和微基准范围。
- `build/benchmark-0.2.0/archive-export.json`：写入、排空、内存、完整性和固定数据导出对照。
- `legacy/python-reference/`：冻结基线，排除生产构建。

本轮支持“本机 300 个模拟生产者处理及导出”的结论。没有重新进行 300 路真实抖音、代理和长时间直播连接验证，也没有声称改写语言会改善公共代理可用率。

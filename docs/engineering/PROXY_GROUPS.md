# 共享出口与代理订阅

本文记录 0.2.1 的共享出口与代理订阅功能。0.2.0 历史安装包不包含这些变更；本版交付验证见评估记录。

## 协议与容量

直播元数据、访客凭据及房间页面使用 HTTPS；消息通过独立的 WSS 长连接接收，心跳与 ACK 复用该连接。HTTP CONNECT 和 SOCKS5h 都可承载 WSS。一个出口可以服务多个房间，但每个房间仍独立建连、确认场次和归档。代理与直连承载的请求都可能受到目标服务限制；地址不同也不保证最终公网出口不同。

全局 8 个名额仅限制正在建连的任务，握手成功后立即释放。每出口最多 2 个正在建连任务和 2 个并行 HTTP 请求，HTTP 起始间隔默认 0.5 秒；这些是本地削峰策略，不是平台公布的安全额度。50 个模拟房间已验证独立连接与故障隔离，不能等同于 50 路真实直播的持续验收。

本轮加入删除并发保护后，再次测试 300 个模拟生产线程：3,000 条/秒阶段持续 10 秒，30,000 条全部提交；6,000 条/秒的 30,000 条突发实际耗时 5.53 秒（约 5,422 条/秒），不能宣称稳定达到 6,000 条/秒。累计 60,000 条、SQLite 完整性检查和并发导出行数均正确，进程峰值工作集约 53.3 MB；此数字不包括真实网络/TLS/签名开销。报告：`build/diagnostics/proxy-groups-archive-benchmark/report.json`。

## 租约与健康生命周期

生产后台启用共享分配，默认让本机直连参与。任务按最少已分配数选择出口，平局轮转；离线轮询和普通重连保持租约。初始健康检查最多等待约 8 秒，避免所有任务立即挤到直连。更改来源或是否使用直连前需停止监控；订阅候选更新可在线进行。

444/429 对该出口新增 HTTP/建连冷却约 60 秒，保留其他已连接房间。单次传输错误不宣告出口永久失效；多个房间的短期故障聚合后冷却并复查。认证拒绝暂停新分配。被移除、过期或已确认失败的出口不再承担新的连接；正在正常收消息的连接自然结束后释放。定期检查不强制拆掉现有 WSS。

首页检测仅验证 HTTP 200 和 TLS，不能证明房间接口或 WSS 可用。对普通网页拒绝不推断代理失效或下播；页面内隐藏的“电脑端暂未支持”提示也不作为自动判断依据。

## 订阅

来源选择「已导入 / URL 订阅」时合并手工记录和启用的订阅。同地址以手工导入为先，订阅之间按保存顺序选择；新候选需健康检查后才分配。刷新失败保留上次成功候选，明确空列表撤销该订阅候选，不关闭已有连接。取消或删除订阅后，旧请求结果不能恢复已删除的地址。

每个订阅默认每 60 分钟刷新；最多 20 个订阅，合并候选最多 5000 条。URL 和代理凭据整体用 DPAPI 加密，界面只展示主机标签。HTTPS、DNS、响应大小及取消边界见 [订阅读取说明](SUBSCRIPTION_SECURITY.md)。

- 三个用户代理：第一枚在代理认证阶段失败；Orem 和 Warsaw 的 HTTP/SOCKS5 首页检查通过。实际配置中的凭据与用户本轮提供值相同，不能将这次失败归因为旧密码。
- 原三个房间：两房确认离线，一房未返回有效元数据，未进入 WSS。
- 用户新给的 100000006000：直连和 Orem 均 HTTP 200、业务 status_code=0，但未获得有效房间信息/roomId；未发起 WSS，不能收消息。页面含提示串但祖先节点 hidden，自动兼容性分类依据不足。一次不带访客凭据的页面补查返回 444，未重试。
- Geonode 一次返回 500 条，其中解析 440 个支持协议候选；这是候选数，不是可用代理数，未批量探测这些地址。

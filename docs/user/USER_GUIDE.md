# 氢看直播使用指南

本指南对应 **0.3.0**，包括红包/福袋活动、共享出口、URL 订阅、记录删除、非 PC 支持标记和首次空列表。适用于 Windows 10 / 11 x64。Tauri 界面需要 Microsoft Edge WebView2；缺失时安装器会运行微软引导程序，此步骤需联网。采集服务随安装包提供，无需另装 Python、Node.js、Excel 或播放器。实际交付验收见 [评估记录](../engineering/EVALUATION.md)。

顶部菜单切换监控看板、实时消息、月度归档、运行日志、代理池和设置。窗口支持拖动、最小化及最大化/还原；重复启动会唤醒现有窗口，避免重复开启后台采集。圆角为界面绘制效果，最大化时取消。

## 监控看板

首次打开不会自动连接。点击「全部开始」，或点击「批量选择」后用卡片右上角复选框选择主播，再点击「开始」。也可在每个卡片上单独开始、停止。操作提交后请查看更新的状态；点击开始不代表平台已经建立连接。

新安装首次打开时主播列表为空，不内置示例直播间。请先添加自己要监控的主播；升级或迁移合法旧配置时，原来保存的主播和自定义昵称会保留，不会自动删除或重新添加主播。

点击「添加主播」，粘贴数字 ID、`https://live.douyin.com/ID` 或 `https://www.douyin.com/follow/live/ID`。支持每行一个、多个完整链接直接相连，重复入口自动跳过。分享短链接需先在浏览器打开，再复制完整地址。查询成功后，尚未自定义的显示名称会更新为平台昵称。

多宫格默认将已确认开播的主播置前，按当前在线人数倒序排列；未开播区域默认折叠，可点击展开。未知状态不会被当作未开播。可切换列表、搜索名字或 ID、筛选状态。看板连续滚动，无需翻页；宫格只绘制屏幕附近的卡片以减少大量任务时的界面负担，滚出屏幕不会停止监控。「批量选择 → 选择可见」仅勾选当前视野内的任务，滚动后可继续选择；「全部开始」「全部停止」作用于完整列表。应用最多保存 500 个任务。看板不再显示「开播优先」说明，底部整条状态栏已移除，内部控件统一使用轻圆角。

顶部显示开播、未开播及待确认等数量。**直播状态和连接状态不同**：停止监控不是下播，查询失败也不是未开播。主播详情显示最近一次直播状态查询时间；连接异常时，上次查询结果可能已过期。只有后台真实查询过的状态才可作为参考。

此前确认直播中的房间，如果接口突然拒绝提供房间信息，会先显示「疑似下播，正在确认」，进行两次间隔约 5 秒的短时复查。持续拒绝后转为重试、状态待确认；只有重新取得明确的未开播状态才确认为下播，不会因错误直接结束场次。这类业务拒绝保留当前代理租约，网络或 TLS 错误按出口健康策略冷却、复查或更换分配，不会因单个房间错误关闭同出口全部连接。提示本身不能区分下播、访问限制或平台风控。

绿色表示已确认开播，灰色用于未开播或未监控，红色表示连接异常。黄色「非 PC 支持」用于在浏览器核实后的手动标记，可在主播详情中添加或清除；同时显示消息是否已连接。标记不改变采集流程，不代表已下播，也不会解除电脑端限制。「等待代理」单独标识，不能据此判断直播状态。

卡片显示主播名称、直播状态、该真实场次已累计的监控时长和当前在线人数。首次监控该场次从实际观察到的开播监控区间计时，不补采加入前的时间；等待未开播的时间不计。同一主播、同一实际场次在停止后恢复或正常退出后重新打开时，继续已保存的累计值，中断和停止间隔不计入；进入新真实场次从零另计。多个入口同时监控同一场次时，重叠区间只计一次。

活跃期间定期保存计时检查点，停止和正常退出时保存已观察值。强制结束或断电只能恢复最近成功检查点，无法保证未落盘的最后几秒，不按停机时长补算。累计计时与服务端真实开播时间分开保存，清理聊天不会重置计时；旧版没有保存过的累计值不会被推测补齐。

当前在线使用最近收到的精确在线数，缺失、未开播或状态待确认时显示「—」，明确收到零时显示 0；累计观看数不会当作在线人数。

点击「打开直播间」会在系统默认浏览器打开公开直播页面，监控应用本身不播放视频。点击卡片其他区域打开详情；展开「连接信息」可查看入口 ID、稳定主播 ID、实际场次、消息计数、查询时间及代理地址。详情中还可改名或展开「独立登录凭据」配置 Cookie。打开详情、切换页面和筛选都不会停止其他任务。

未开播时持续检查，连接失败自动退避重试。无法确认真实主播或场次、收到不一致的场次 ID、内容归档失败时会暂停对应房间并显示原因，处理后可重新开始。界面消息计数表示本轮任务新增入库条数，重复消息不计数；停止后重新开始会重置本轮计数，历史库仍保留。

「全部停止」会请求停止采集。关闭主窗口会请求停止后台并等待归档刷新；等待应用退出后再进行备份。移除任务会停止对应监控，但保留历史归档。

## 实时消息和运行日志

顶部「实时消息」显示聊天、礼物、点赞、关注/分享、粉丝团、表情和红包/福袋，可按主播或类型筛选。进入直播间消息不在此显示，继续归档和导出。「暂停滚动」暂停刷新显示，采集和归档继续；暂停时切换分类保持在暂停时已读取的数据范围，恢复后显示最近消息。

红包/福袋包含活动通知、结果、福袋同步和红包预告等协议消息，详情只使用消息实际提供的字段；未知发送人 ID、名字和时间保持空值。界面及导出的「消息内容」为事实摘要，结构化详情另存数据库 `payload_json`。0.2.3 根据公开房间的脱敏真实包验证新增同步和预告的解码到归档链路；这不保证平台向所有连接下发全部活动。游客连接可能缺少礼物推送，仍需独立登录凭据对照，详见 [消息诊断](../engineering/MESSAGE_DELIVERY_0.2.3.md)。

实时界面每两秒从本机归档读取最近 150 条匹配消息，打开页面或切换分类后也能看到历史匹配记录，不受全局事件显示缓存挤占。完整内容可通过月度导出查看；运行日志页面展示最近 200 条。筛选和暂停不会删除已入库记录。

「运行日志」单独显示连接、重试、停止、直播结束和错误，不进入内容导出。当前在线人数更新看板，并按真实场次保存独立在线统计，不进入实时消息、聊天计数或原始聊天月导出。累计观看统计、排行和其他房间统计不解析为内容。应用不播放、不录制直播画面或声音。

## 主播和场次如何归档

程序从平台取得稳定的 `anchor_id`，据此合并同一主播的多个入口和不同场次。网址中的 `web_rid` 只是访问入口；「直播间场次」使用平台实际 `room_id`，不用本地序号或首次连接时间代替。

同一实际场次的断线重连、停止后重启以及重复入口不会制造新场次。有服务端消息 ID 时按「主播 + 场次 + 消息 ID」去重；缺少消息 ID 时保留收到的记录，不按相似内容推测去重。

开播时间只有服务端明确返回时才保存。首次检测、首次连接和首条消息时间不冒充开播时间。未知发送人 ID 留空，昵称单独保存；发送时间未知时留空，接收时间另有记录。

## 月度归档与导出

1. 打开「月度归档」。主播列表只包含新内容库中已有消息的主播；移除任务后仍可选择历史主播，同名主播用稳定 ID 区分。
2. 选择月份、一个或多个主播、消息类型及 XLSX / CSV 格式。
3. 点击「选择保存位置并导出」。任务在后台执行，监控可继续运行；最多同时执行两个导出。
4. 在「导出记录」查看本次运行中的完成、取消或错误，以及导出条数、未知字段数量、CSV 保护前缀数量。正在执行的任务可以取消。

导出读取一致的数据快照，随后新收到的内容可再次导出。取消或导出失败不会覆盖原有目标文件。文件固定七列：

| 列 | 内容 |
| --- | --- |
| 主播 | 消息归档时的显示名称；选择与聚合依据稳定主播 ID。 |
| 直播间场次 | 实际 `room_id` 文本，不是网址入口 ID。 |
| 发消息人ID | 服务端发送人 ID；未知为空，不用昵称补齐。 |
| 发消息人名字 | 已归档的 `sender_name` 昵称；未知为空，不用 ID 补齐。 |
| 消息类型 | 弹幕、礼物、点赞、进场、关注/分享、粉丝团、表情弹幕或红包/福袋。 |
| 消息内容 | 正文或互动内容，不带界面时间、主播等显示前缀。 |
| 发消息时间 | 北京时间及 `+08:00` 时区；服务端未提供时为空。 |

月份使用 **Asia/Shanghai**，范围为当月 1 日 00:00（含）至下月 1 日 00:00（不含）。优先按发送时间归月；缺少发送时间时按接收月份纳入，发送时间列仍为空，并提示数量。这些记录不能用于精确判断实际发送月份。

多主播 XLSX 为每位主播创建独立工作表，以主播显示名命名；名称中的非法字符替换为下划线，按 Excel 的 31 个 UTF-16 单位上限截断；空名称使用主播 ID，重名和续表添加数字后缀。每个所选主播都会有工作表，当月或所选消息类型没有记录时仅保留表头。超过单表行数限制时续表，不静默截断。CSV 不支持工作表，仍合并为七列平表。

默认文件名示例：选择多位主播为 `直播消息-2026-10.xlsx`；选择一位主播为 `直播消息-主播名-2026-10.xlsx`。CSV 使用相同命名规则及 `.csv` 扩展名。文件名中的系统不允许字符会处理，保存位置和文件名均可修改。

**推荐 XLSX**：长场次 ID、发送人 ID 和内容以文本单元格保存，避免 Excel 改写长数字。CSV 使用 UTF-8 BOM，直接双击可能被 Excel 转为数值；请通过导入功能将 ID 列指定为文本。

CSV 对可能被识别为公式的文本添加单引号保护前缀，并提示处理数量，因此相应单元格可能比原文多一个前缀，数据库原文不变。XLSX 不把内容写成公式；遇到 Excel 无法原样保存的超长单元格或控制字符，会提示改用 CSV。

导出覆盖本机已采集且成功入库的记录，不从抖音补采整月历史，不受当前界面显示条数限制。

## 设置与原生采集

可在设置切换抖音美好体和寒蝉半圆体，查看原生后台运行指标与本地数据目录。0.3.0 全部采集、签名和归档在 Rust 中运行，不需要安装 Python 或 Node。

没有登录 Cookie 输入入口；应用只使用临时游客会话。旧配置中的登录字段不解密或发送。新礼物记录和实时礼物展示已停用，历史礼物仍可在归档中筛选导出。

## 共享出口与代理池

默认启用 `proxy.scdn.io` 公共代理池，固定以 `protocol=https` 获取候选。公共池在代理模式开始监控，或手动点击「代理池 → 获取并检测」后获取并检测；打开应用本身不触发公共池拉取。已保存且启用的 URL 订阅仍按到期间隔自动刷新，启动时已到期即可联网获取候选。代理池页面显示首页通过、已分配、检测中和失败数量，以及房间当前分配的地址和检测延迟。「首页通过」表示当前可继续分配的已通过首页初检代理，可能已承载任务；已分配数统计任务租约，不是互斥代理数量，也不代表已验证直播消息连接。

使用自己的代理时，点击「导入代理」，粘贴列表或选择 JSON、TXT、CSV、TSV 文件。支持 JSON 数组、`IP:端口:账号:密码`、代理 URL 或带列名的表格；账号密码也可同时留空。JSON 可提供 `ip`、`port`、`protocol`、`username`、`password`，以及可选的城市和到期时间。未注明协议的文本使用窗口中选定的协议，默认 SOCKS5；有明确协议的 JSON 或 URL 优先。SOCKS5 统一使用远端 DNS，HTTP 使用 CONNECT；HTTP 认证需 ASCII 账号密码，SOCKS5 各字段不超过 255 个 UTF-8 字节。

点击「识别预览」查看新增、更新、未变化及无效条目，再点击「导入或更新」。同一地址的账号密码或协议有变化时会更新，避免一直使用旧认证。预览和管理列表只显示地址、协议、认证是否配置及检测状态，不回显账号密码。导入的凭据整体使用当前 Windows 用户的 DPAPI 加密保存，不写明文代理 URL；原始导入文件仍由用户保管，应用不会替它清除明文内容。最多保存 5,000 条导入代理，可在「管理已导入代理」中移除。

停止全部监控并等待连接退出后，将「代理来源」切换为「已导入 / URL 订阅」，点击「检测导入代理」，确认结果后再启用代理并开始监控。导入和检测不会自动开启监控；代理关闭时也能检测所选来源。已导入来源每批最多检测 50 个地址，列表不足时以实际数量为准，过期条目不会被分配。切换来源或网络模式需要全部停止，避免任务中途更换出口。ProxyHub、ProxyClean 目前没有自动抓取入口；本次来源评估不等于应用已替换默认公共池。

代理关闭时也可以「获取并检测」，先准备备用候选。检测不会启用代理或改变正在运行的直连任务；之后启用时复用这批仍有效的检测结果，不必丢弃重来。候选有有效期，也可能提前失效，不能保证检测后永久可用；退出应用会清理备用池。

公共来源每次手动检测目标为 **50 个新候选地址**，跳过当前池已有地址、重复地址和本次应用运行期间已失败的地址。失败排除在关闭、重新启用及备用池之间共享，重启应用后可重新检测。批次仍在进行时再次点击不会叠加请求。

页面区分目标数、实际检测数与通过数；50 个候选不等于 50 个可用代理。公共来源获取预算为最多 10 次请求、90 秒，连续三次没有新候选也会提前停止拉取；已排队的检测完成后收尾，并提示未补足的原因。因此整个批次可能超过 90 秒。可根据实际通过数量决定是否启用。

同一出口可分配多个房间，每个房间保持独立消息连接；默认勾选「直连参与均衡」，本机直连和已检测代理一起按任务数分配。取消该选项后只使用代理，不会自行回退直连。租约贯穿开播查询、访客 Cookie、房间页面和 WSS。出口有独立请求节流与建连名额；444/429 会冷却新请求，正常在线房间继续收消息。订阅移除或凭据变更时，旧连接结束后再换出口。等待名额只限制建连过程，不是同时在线数量上限。

需要切换直连时，先在看板「全部停止」，等待正在进行的连接退出，再取消「代理池 → 启用代理」。启用代理也遵循同一规则；切换不会自动重启任务，请回看板重新开始。程序不使用系统环境代理覆盖这一选择。

代理通过 HTTP CONNECT 或 SOCKS5 隧道承载经过证书验证的 HTTPS / WSS 连接，不将 Cookie 降级为明文 HTTP 请求。初检只接受抖音首页 HTTP 200，不跟随或接受重定向；随后开始任务才使用同一代理查询房间并连接消息服务。提示「经代理访问目标站点时，TLS 连接被提前关闭」表示代理路径上的加密连接中断，单凭此错误不能确定是哪一端关闭。代理可失效或被平台限制；一次 HTTPS 检测成功不保证直播消息长连接成功、长期稳定或有足够多可用代理。实际探测结果见 [评估记录](../engineering/EVALUATION.md)。

2026-10-14 扩测了 SCDN 固定 HTTPS 来源的 500 个候选地址：10 个地址、9 个不同 IP 通过抖音 HTTPS 首页响应头检查（HTTP 200）。这项检查没有验证完整页面、房间接口或 WebSocket。随后选用 7 个曾通过检查的地址，对三个指定房间共做 21 次元数据查询，均因超时或 TLS 连接/验证失败，没有进入消息连接测试。后续该来源另 700 个候选也没有实际消息成功。这些是特定来源和时段的结果，不能推断全部公共代理不可用；ProxyHub 和 ProxyClean 已有短时真实互动消息成功记录，详见 [代理来源评估](../engineering/PROXY_SOURCES_REVIEW.md)。代理不足时可保留等待，或在全部停止后明确切换直连。

用户提供的另一批 33 个认证 SOCKS5 节点此次均未通过：30 个在 SOCKS 用户名密码认证阶段被拒绝，3 个超时；独立原生 curl 单节点复核也认证拒绝，尚未到抖音接口。这不等于直播下播，也不能仅凭该错误区分账号、密码、套餐或访问策略问题。此次没有房间或 WSS 成功，可测 SOCKS TCP 载荷合计 900 字节；该数不含 TCP/IP 开销、重传、未读缓冲和独立 curl 对照握手，不能把它当完整账单。此次诊断未将凭据另存为明文或写入报告。

## URL 订阅

打开「代理池 → URL 订阅」，填入 HTTPS 地址并选择刷新间隔，支持 Geonode、JSON 数组和逐行代理地址。添加后会异步读取，归入「已导入 / URL 订阅」来源；不会自动修改当前来源或开始监控。刷新失败保留上次成功结果，可手动刷新或移除。订阅 URL 与认证信息加密保存，页面不显示路径和查询令牌。

## 删除已保存的聊天记录

在「月度归档」先勾选主播，再点击顶部「删除记录」。可选择指定月份、指定场次，或这些主播的全部记录；月份与场次同时选择时取交集。场次列表可按月份筛选并分页加载。删除包含该范围的所有消息类型，不采用导出区的类型勾选。

预览会显示消息数与场次数，确认后才删除。须先停止相关主播的监控并等待对应导出结束；身份尚未确认的活跃任务也需先停止，避免在途写入。删除通过后台任务及数据库事务执行，期间可以收起进度窗口，完成后会通知；退出应用会请求取消删除，事务观察到取消时回滚尚未提交的更改，取消生效前已完成提交的删除不撤回。保留其他主播、其他月份和其他场次，不会删除监控任务、运行日志或已有导出文件。完成后的删除无法撤回，请先导出需要保留的内容。

## 数据、旧版本与备份

点击顶部文件夹按钮或「设置 → 打开数据目录」。默认目录为 `%LOCALAPPDATA%\DouyinLiveMonitor`：

- `messages.sqlite3`：聊天与互动、主播、真实场次和时间来源。
- `logs\YYYY-MM-DD.jsonl`：按北京时间日期保存的运行日志。
- `engine.log`：桌面后台诊断日志。
- `config.json`：主播列表、身份缓存、加密 Cookie 和加密导入代理配置。
- `messages\...`：如有，这是旧版 JSONL，升级后保留原样。

旧 JSONL **不自动导入，也不混入新月导出**。缺失的真实场次、发送人 ID、发送时间或稳定主播 ID 无法可靠回填，需要旧数据时请保留原文件。

备份前关闭应用，等待后台进程退出，再复制整个数据目录。SQLite 运行期间可能存在 `messages.sqlite3-wal`、`messages.sqlite3-shm`，不要在运行时只复制主数据库文件。内容写入失败会暂停对应房间，未成功保存的消息不保证能够恢复。

0.2.2 将旧 schema v1/v2 内容库事务迁移到 v3，保留原记录并增加场次分析表。旧版不能打开 v3；降级需使用升级前完整备份，不要手改数据库版本号。详见 [分析与升级边界](../engineering/SESSION_QUALITY_0.2.2.md)。

从 Windows「设置 → 应用」卸载。卸载保留用户数据目录；彻底清除前先完成备份，再手动删除该目录。

## 版本日志与更新

在「设置 → 关于与更新」查看当前版本，点击「更新日志」阅读详细说明。「检查更新」只查询版本，不自动安装，监控中也可检查。

默认启动后及每小时检查更新，可在设置关闭。发现版本后先查看更新内容，确认「暂停监控并更新」。下载并验签完成后自动保存原活动任务、暂停监控并落盘，再安装并重新打开恢复；下载或验签失败继续监控，导出/删除仍在执行时等待完成。

0.1.0 是正式 NSIS 更新渠道的起点，0.2.2 继续沿用同一渠道和签名公钥。已安装 0.1.0 / 0.1.1 / 0.2.0 可在新清单上传后检查更新，也可关闭应用后手动运行 0.2.2 安装器。使用旧 Inno 试制版时，先关闭旧版，再手动安装当前正式版到新的默认目录；不要选择旧 Inno 安装目录。两者沿用同一用户数据目录。安装同版本后检查更新显示最新版本属于正常情况，后续发布必须提高版本号。

发布者需先上传安装包，再发布 `latest.json`。上传前或网络不可用时，检查更新可能失败，不影响当前程序使用。CDN 发布方法见 [发布说明](../release/CDN_RELEASE.md)。

## 场次有效发言与更新

主播详情中查看直播场次数，按月份筛选，每页 20 场。当前场次优先显示，零消息也登记。有效发言人数按账号 ID 去重，至少一条正常互动即可；未知 ID 不虚构人数。同人 60 秒同文至少 3 条、60 秒至少 20 条/10 人、整场至少 50 条/20 人会回溯排除对应组；保留原文和判定样本。阈值可按主播修改，已确认参与口令可按场填写，未核实时间保留待判定。AI 暂未加入。

历史和新增消息分批分析，统计中或需确认时有效率为「—」。可重新分析或暂停重算；分析导出与原始消息导出独立。监控有缺口时不补造内容，覆盖标为部分监控或覆盖未知。

设置默认「自动检查更新 · 每小时」，启动后检查，此后每小时检查，关闭后只手动检查。有更新可查看详细日志，点击暂停监控并更新并确认。下载或签名失败继续监控；验证通过才保存活动任务列表、暂停并落盘。更新后重新打开会恢复这些任务，手动停止的任务保持停止；同场次累计监控时长不含更新停机。安装启动失败尝试恢复当前任务。此能力从 0.2.2 开始提供，旧版发起本次升级仍按旧版流程。


## 在线人数刷新与场次在线指标

看板顶部「刷新人数」仅刷新正在监控的开播任务，沿用各自出口并显示进度；重复点击不创建新批次。场次表新增最高在线、分钟均在线与有效发言／在线。均在线先对各分钟内实际采样求均值，再对已采样分钟等权平均；缺失分钟不补零，同场恢复继续。占比为整场去重有效发言人数除以均在线，可能超过 100%；无采样、分母为零或分析未完成显示「—」。场次分析导出在原 14 列后增加四列，原始聊天七列不变。详见 [0.2.4 更新说明](../../release-notes/0.2.4.md)。


「有效发言占比」使用有效发言人数 ÷ 总发言人数，两个数量都按本场账号 ID 去重，区别于分母采用均在线的「有效／在线」。总发言人数为零或分析未完成时显示「—」。场次分析 XLSX/CSV 使用相同列名和口径。

# 氢看直播使用指南

本指南包括监控看板、直播打点、切片下载、消息流、红包/福袋回看、数据导出、代理和诊断设置。适用于 Windows 10 / 11 x64。Tauri 界面需要 Microsoft Edge WebView2；缺失时安装器会运行微软引导程序，此步骤需联网。采集服务随安装包提供，无需另装 Python、Node.js、Excel 或播放器。实际交付验收见 [评估记录](../engineering/EVALUATION.md)。

导航包含「监控看板」「导出数据」「录像下载」「设置」。实时消息通过看板中的「消息流」进入，代理和诊断收在设置的折叠区中。窗口支持拖动、最小化及最大化/还原；重复启动会唤醒现有窗口，避免重复开启后台采集。圆角为界面绘制效果，最大化时取消。

## 监控看板

首次打开不会自动连接。点击「全部开始」，或点击「批量选择」后用卡片右上角复选框选择主播，再点击「开始」。也可在每个卡片上单独开始、停止。操作提交后请查看更新的状态；点击开始不代表平台已经建立连接。

新安装首次打开时主播列表为空，不内置示例直播间。请先添加自己要监控的主播；升级或迁移合法旧配置时，原来保存的主播和自定义昵称会保留，不会自动删除或重新添加主播。

点击「添加主播」，粘贴数字 ID、`https://live.douyin.com/ID` 或 `https://www.douyin.com/follow/live/ID`。支持每行一个、多个完整链接直接相连，重复入口自动跳过。分享短链接需先在浏览器打开，再复制完整地址。查询成功后，尚未自定义的显示名称会更新为平台昵称。

添加时可以填写标签，同一批新主播共用这些标签；重复入口保留原标签。多个标签用逗号分隔，每位主播最多 20 个、每个最多 24 字。点击卡片上的标签编辑入口，或在「主播设置 → 标签」修改；「批量选择 → 设置标签」可以统一替换所选主播的标签，留空清除。看板可以组合标签、名字/ID 和直播状态筛选，也可以选择「无标签」。标签随真实主播身份保存，移除监控后仍可用于历史数据导出。新入口识别为已有主播时，优先沿用该主播已保存的标签。

多宫格默认将已确认开播的主播置前，按当前在线人数倒序排列；未开播区域默认折叠，可点击展开。未知状态不会被当作未开播。可切换列表、搜索名字或 ID、筛选状态。看板连续滚动，无需翻页；宫格只绘制屏幕附近的卡片以减少大量任务时的界面负担，滚出屏幕不会停止监控。「批量选择 → 选择可见」仅勾选当前视野内的任务，滚动后可继续选择；「全部开始」「全部停止」作用于完整列表。应用最多保存 500 个任务。看板不再显示「开播优先」说明，底部整条状态栏已移除，内部控件统一使用轻圆角。

顶部显示开播、未开播及待确认等数量。**直播状态和连接状态不同**：停止监控不是下播，查询失败也不是未开播。主播详情显示最近一次直播状态查询时间；连接异常时，上次查询结果可能已过期。只有后台真实查询过的状态才可作为参考。

此前确认直播中的房间，如果接口突然拒绝提供房间信息，会先显示「疑似下播，正在确认」，进行两次间隔约 5 秒的短时复查。持续拒绝后转为重试、状态待确认；只有重新取得明确的未开播状态才确认为下播，不会因错误直接结束场次。这类业务拒绝保留当前代理租约，网络或 TLS 错误按出口健康策略冷却、复查或更换分配，不会因单个房间错误关闭同出口全部连接。提示本身不能区分下播、访问限制或平台风控。

绿色表示已确认开播，灰色用于未开播或未监控，红色表示连接异常。黄色「非 PC 支持」用于在浏览器核实后的手动标记，可在主播详情中添加或清除；同时显示消息是否已连接。标记不改变采集流程，不代表已下播，也不会解除电脑端限制。「等待代理」单独标识，不能据此判断直播状态。

卡片显示主播名称、直播状态、该真实场次已累计的监控时长和当前在线人数。首次监控该场次从实际观察到的开播监控区间计时，不补采加入前的时间；等待未开播的时间不计。同一主播、同一实际场次在停止后恢复或正常退出后重新打开时，继续已保存的累计值，中断和停止间隔不计入；进入新真实场次从零另计。多个入口同时监控同一场次时，重叠区间只计一次。

活跃期间定期保存计时检查点，停止和正常退出时保存已观察值。强制结束或断电只能恢复最近成功检查点，无法保证未落盘的最后几秒，不按停机时长补算。累计计时与服务端真实开播时间分开保存，清理聊天不会重置计时；旧版没有保存过的累计值不会被推测补齐。

计时按每位数字显示独立底片和中缝，仅变化的数字执行翻页。系统启用减少动态效果时直接更新数字；首次显示或滚动进入视野不会假装经过了一秒。

当前在线使用最近收到的精确在线数，缺失、未开播或状态待确认时显示「—」，明确收到零时显示 0；累计观看数不会当作在线人数。

点击「打开直播间」会在系统默认浏览器打开公开直播页面，监控应用本身不播放视频。点击卡片其他区域打开详情；在「连接信息」查看入口 ID、稳定主播 ID、实际场次、消息计数、查询时间及代理地址，在「主播设置」改名或添加非 PC 支持标记。打开详情、切换页面和筛选都不会停止其他任务。

未开播时持续检查，连接失败自动退避重试。无法确认真实主播或场次、收到不一致的场次 ID、内容归档失败时会暂停对应房间并显示原因，处理后可重新开始。界面消息计数表示本轮任务新增入库条数，重复消息不计数；停止后重新开始会重置本轮计数，历史库仍保留。

「全部停止」会请求停止采集。关闭主窗口会请求停止后台并等待归档刷新；等待应用退出后再进行备份。移除任务会停止对应监控，但保留历史归档。

## 直播打点与精选下载

开播主播卡片上的旗标可以立即打点。进入主播详情的「直播打点」，还可以填写标题、修改备注、勾选精选。打点按后台记录的实际时刻绑定当前真实场次，重启后保留；历史场次不能补记为当前直播打点。

有录播后，点击时间轴旗标或打点时间可定位。设置打点前后各保留多少秒，点击「选片」可继续调整已有框选区间，或勾选多条后「下载精选」。默认保留前 15 秒、后 30 秒，单个片段最长 15 分钟。没有录播或对应时间处于真实录像缺口时，不创建虚假的片段。

回看时间轴以真实世界的几点到几点显示。在「设置 → 回看时间」选择时区，默认为中国时区 `Asia/Shanghai`。有绝对时间标记时使用录像自身时间；没有可靠锚点则保留相对进度并说明时间尚未对齐。时区设置和弹幕偏移不会改写原始记录或切片的媒体位置。

「录像下载」按北京时间的下载任务创建日期分组，支持日期、状态和标题、主播、场次、文件名关键词检索，每页 30 条。历史任务保存在独立索引中，不再随最近队列清理；旧版本仍保存的记录会迁入，已经被旧版清理的记录无法补回。原有取消、重试和打开文件夹操作保留。

在「设置 → 录像下载」选择下载位置，分别填写文件夹规则和文件名规则。例如文件夹 `{date}/{anchor}`、文件名 `{title}_{start}-{end}.mp4` 会按场次日期和主播建立子目录。可以插入主播、场次 ID、标题、年月日、片段起止、下载日期等变量，保存前会显示路径预览。同名文件自动加序号，变量内容不会变成额外目录或越过下载位置。

## 消息流和运行日志

在「监控看板」点击「消息流」，查看聊天、点赞、关注/分享、粉丝团、表情和红包/福袋，可按主播或类型筛选。进入直播间消息不在此显示，继续归档和导出。新礼物采集与实时展示已停用，历史礼物可在导出数据中筛选。「暂停滚动」暂停刷新显示，采集和归档继续；暂停时切换分类保持在暂停时已读取的数据范围，恢复后显示最近消息。

红包/福袋包含活动通知、结果、福袋同步和红包预告等协议消息，详情只使用消息实际提供的字段；未知发送人 ID、名字和平台时间保持空值。界面及导出的「消息内容」为事实摘要，结构化详情另存数据库 `payload_json`。0.2.3 根据公开房间的脱敏真实包验证新增同步和预告的解码到归档链路；这不保证平台向所有连接下发全部活动。此前消息下发排查范围见 [消息诊断](../engineering/MESSAGE_DELIVERY_0.2.3.md)。

消息流每两秒从本机归档读取最近 150 条匹配消息，打开页面或切换分类后也能看到历史匹配记录，不受全局事件显示缓存挤占。完整内容可通过「导出数据」查看。筛选和暂停不会删除已入库记录。

「设置 → 诊断」中的调试模式默认关闭。关闭时，正常连接、停止和未开播轮询不进入日志队列或磁盘，真实异常继续保存；开启后显示最近 200 条运行日志并记录详细连接过程。关闭后停止新增详细日志，已保存文件保留。运行日志不进入内容导出，磁盘最多保留两份、各 8 MiB。

当前在线人数更新看板，并按真实场次保存独立在线统计，不进入消息流、聊天计数或原始聊天月导出。累计观看统计、排行和其他房间统计不解析为内容。应用不播放、不录制直播画面或声音。

## 主播和场次如何归档

程序从平台取得稳定的 `anchor_id`，据此合并同一主播的多个入口和不同场次。网址中的 `web_rid` 只是访问入口；「直播间场次」使用平台实际 `room_id`，不用本地序号或首次连接时间代替。

重启后会恢复已保存的真实主播身份与最近场次，未开播也可查看本机历史，无需等待再次开播。旧版身份信息为空时，只从归档中能明确对应直播间入口 ID 的记录恢复，不按昵称猜测；无法可靠对应时保持待确认。恢复历史不代表正在直播，开播状态仍以平台查询为准。

同一实际场次的断线重连、停止后重启以及重复入口不会制造新场次。有服务端消息 ID 时按「主播 + 场次 + 消息 ID」去重；缺少消息 ID 时保留收到的记录，不按相似内容推测去重。

开播时间只有服务端明确返回时才保存。首次检测、首次连接和首条消息时间不冒充开播时间。未知发送人 ID 留空，昵称单独保存；发送时间未知时留空，接收时间另有记录。

## 导出数据

1. 打开「导出数据」（原月度归档入口）。主播列表只包含新内容库中已有消息的主播；移除任务后仍可选择历史主播，同名主播用稳定 ID 区分。
2. 选择月份、一个或多个主播、消息类型及 XLSX / CSV 格式。

   可先按标签筛选；切换标签会选中当前筛选结果，「全选筛选结果」只选择匹配的主播，「清空」取消选择。导出仅包含当前标签下实际勾选的主播。设置中的「数据备份 → 指定主播」也可以按标签筛选导出，标签会随备份保留，增量导入时与已有标签合并去重。
3. 点击「选择保存位置并导出」。任务在后台执行，监控可继续运行；最多同时执行两个导出。
4. 在「导出记录」查看本次运行中的完成、取消或错误，以及导出条数、未知字段数量、CSV 保护前缀数量。正在执行的任务可以取消。

导出读取一致的数据快照，随后新收到的内容可再次导出。取消或导出失败不会覆盖原有目标文件。文件固定七列：

| 列 | 内容 |
| --- | --- |
| 主播 | 消息归档时的显示名称；选择与聚合依据稳定主播 ID。 |
| 直播间场次 | 实际 `room_id` 文本，不是网址入口 ID。 |
| 发消息人ID | 服务端发送人 ID；未知为空，不用昵称补齐。 |
| 发消息人名字 | 已归档的 `sender_name` 昵称；未知为空，不用 ID 补齐。 |
| 消息类型 | 弹幕、礼物、点赞、进场、关注/分享、粉丝团、表情弹幕或红包/福袋。 |
| 消息内容 | 正文或互动内容，不带界面时间、主播等显示前缀。 |
| 发消息时间 | 北京时间及 `+08:00` 时区；服务端未提供时为空。 |

月份使用 **Asia/Shanghai**，范围为当月 1 日 00:00（含）至下月 1 日 00:00（不含）。优先按发送时间归月；缺少发送时间时按接收月份纳入，发送时间列仍为空，并提示数量。这些记录不能用于精确判断实际发送月份。

多主播 XLSX 为每位主播创建独立工作表，以主播显示名命名；名称中的非法字符替换为下划线，按 Excel 的 31 个 UTF-16 单位上限截断；空名称使用主播 ID，重名和续表添加数字后缀。每个所选主播都会有工作表，当月或所选消息类型没有记录时仅保留表头。超过单表行数限制时续表，不静默截断。CSV 不支持工作表，仍合并为七列平表。

默认文件名示例：选择多位主播为 `直播消息-2026-10.xlsx`；选择一位主播为 `直播消息-主播名-2026-10.xlsx`。CSV 使用相同命名规则及 `.csv` 扩展名。文件名中的系统不允许字符会处理，保存位置和文件名均可修改。

**推荐 XLSX**：长场次 ID、发送人 ID 和内容以文本单元格保存，避免 Excel 改写长数字。CSV 使用 UTF-8 BOM，直接双击可能被 Excel 转为数值；请通过导入功能将 ID 列指定为文本。

CSV 对可能被识别为公式的文本添加单引号保护前缀，并提示处理数量，因此相应单元格可能比原文多一个前缀，数据库原文不变。XLSX 不把内容写成公式；遇到 Excel 无法原样保存的超长单元格或控制字符，会提示改用 CSV。

导出覆盖本机已采集且成功入库的记录，不从抖音补采整月历史，不受当前界面显示条数限制。

## 设置与原生采集

可在设置切换抖音美好体和寒蝉半圆体，查看原生后台运行指标与本地数据目录。0.3.0 全部采集、签名和归档在 Rust 中运行，不需要安装 Python 或 Node。

没有登录 Cookie 输入入口；应用只使用临时游客会话。旧配置中的登录字段不解密或发送。新礼物记录和实时礼物展示已停用，历史礼物仍可在归档中筛选导出。

## 共享出口与代理池

新安装默认关闭代理池，使用本机直连；升级保留旧配置中明确保存的启用偏好，不会强制关闭。代理入口位于「设置 → 代理池」，默认折叠。代理关闭时，后台不自动获取公共代理，也不自动刷新已保存的 URL 订阅；手动「获取并检测」或刷新订阅仍可使用。启用代理后，后台可按需获取公共候选并刷新到期订阅。

公共来源使用 `proxy.scdn.io`，固定以 `protocol=https` 获取候选。展开设置中的代理区可查看首页通过、已分配、检测中和失败数量，以及房间当前分配的地址和检测延迟。「首页通过」表示当前可继续分配的已通过首页初检代理，可能已承载任务；已分配数统计任务租约，不是互斥代理数量，也不代表已验证直播消息连接。

使用自己的代理时，点击「导入代理」，粘贴列表或选择 JSON、TXT、CSV、TSV 文件。支持 JSON 数组、`IP:端口:账号:密码`、代理 URL 或带列名的表格；账号密码也可同时留空。JSON 可提供 `ip`、`port`、`protocol`、`username`、`password`，以及可选的城市和到期时间。未注明协议的文本使用窗口中选定的协议，默认 SOCKS5；有明确协议的 JSON 或 URL 优先。SOCKS5 统一使用远端 DNS，HTTP 使用 CONNECT；HTTP 认证需 ASCII 账号密码，SOCKS5 各字段不超过 255 个 UTF-8 字节。

点击「识别预览」查看新增、更新、未变化及无效条目，再点击「导入或更新」。同一地址的账号密码或协议有变化时会更新，避免一直使用旧认证。预览和管理列表只显示地址、协议、认证是否配置及检测状态，不回显账号密码。导入的凭据整体使用当前 Windows 用户的 DPAPI 加密保存，不写明文代理 URL；原始导入文件仍由用户保管，应用不会替它清除明文内容。最多保存 5,000 条导入代理，可在「管理已导入代理」中移除。

停止全部监控并等待连接退出后，将「代理来源」切换为「已导入 / URL 订阅」，点击「检测导入代理」，确认结果后再启用代理并开始监控。导入和检测不会自动开启监控；代理关闭时也能检测所选来源。已导入来源每批最多检测 50 个地址，列表不足时以实际数量为准，过期条目不会被分配。切换来源或网络模式需要全部停止，避免任务中途更换出口。ProxyHub、ProxyClean 目前没有自动抓取入口；本次来源评估不等于应用已替换默认公共池。

代理关闭时也可以「获取并检测」，先准备备用候选。检测不会启用代理或改变正在运行的直连任务；之后启用时复用这批仍有效的检测结果，不必丢弃重来。候选有有效期，也可能提前失效，不能保证检测后永久可用；退出应用会清理备用池。

公共来源每次手动检测目标为 **50 个新候选地址**，跳过当前池已有地址、重复地址和本次应用运行期间已失败的地址。失败排除在关闭、重新启用及备用池之间共享，重启应用后可重新检测。批次仍在进行时再次点击不会叠加请求。

页面区分目标数、实际检测数与通过数；50 个候选不等于 50 个可用代理。公共来源获取预算为最多 10 次请求、90 秒，连续三次没有新候选也会提前停止拉取；已排队的检测完成后收尾，并提示未补足的原因。因此整个批次可能超过 90 秒。可根据实际通过数量决定是否启用。

同一出口可分配多个房间，每个房间保持独立消息连接；默认勾选「直连参与均衡」，本机直连和已检测代理一起按任务数分配。取消该选项后只使用代理，不会自行回退直连。租约贯穿开播查询、访客 Cookie、房间页面和 WSS。出口有独立请求节流与建连名额；444/429 会冷却新请求，正常在线房间继续收消息。订阅移除或凭据变更时，旧连接结束后再换出口。等待名额只限制建连过程，不是同时在线数量上限。

需要切换直连时，先在看板「全部停止」，等待正在进行的连接退出，再取消「设置 → 代理池 → 启用代理」。启用代理也遵循同一规则；切换不会自动重启任务，请回看板重新开始。程序不使用系统环境代理覆盖这一选择。

代理通过 HTTP CONNECT 或 SOCKS5 隧道承载经过证书验证的 HTTPS / WSS 连接，不将 Cookie 降级为明文 HTTP 请求。初检只接受抖音首页 HTTP 200，不跟随或接受重定向；随后开始任务才使用同一代理查询房间并连接消息服务。提示「经代理访问目标站点时，TLS 连接被提前关闭」表示代理路径上的加密连接中断，单凭此错误不能确定是哪一端关闭。代理可失效或被平台限制；一次 HTTPS 检测成功不保证直播消息长连接成功、长期稳定或有足够多可用代理。实际探测结果见 [评估记录](../engineering/EVALUATION.md)。

## 删除已保存的聊天记录

## 数据、旧版本与备份

点击顶部文件夹按钮或「设置 → 打开数据目录」。默认目录为 `%LOCALAPPDATA%\DouyinLiveMonitor`：

- `messages.sqlite3`：聊天与互动、主播、真实场次和时间来源。
- `session-marks.json`：直播打点、标题和备注。
- `clips.sqlite3`：下载任务历史；旧版 `clips.json` 保留原样并迁入历史索引。
- `logs\runtime.jsonl`、`logs\runtime.previous.jsonl`：异常记录，以及调试模式开启期间的详细运行日志；有界轮转。
- `config.json`：主播列表、身份缓存、调试偏好、代理设置及加密的代理和 AI 凭据。
- `messages\...`：如有，这是旧版 JSONL，升级后保留原样。

旧 JSONL **不自动导入，也不混入新月导出**。缺失的真实场次、发送人 ID、发送时间或稳定主播 ID 无法可靠回填，需要旧数据时请保留原文件。

在「设置 → 备份与恢复」导出可重新导入的数据备份。默认备份全部主播，也可切到「指定主播」，搜索、勾选后仅导出所选主播的完整关联记录；未选择任何主播不能导出。应用使用数据库快照，监控期间也可导出；现有 XLSX / CSV 仍用于查看和分析，不是可恢复的备份格式。内容写入失败会暂停对应房间，未成功保存的消息不保证能够恢复。

备份包括直播场次、消息与红包福袋记录、在线统计、分析规则与结果、打点、下载任务记录、主播列表、命名规则、显示时区、字体及回看校准。不包含录像文件、临时缓存、日志、服务密钥或代理凭据。迁移到其他设备后，重新填写服务 Key，下载目录使用新设备的本地目录。

导入时先选择备份文件，核对备份时间与记录数量，再「确认增量导入」。只补充缺失的主播和记录，重复导入不会重复累计；已有非空内容、设置、下载文件位置及本机凭据优先保留，界面偏好也只补缺失项。导入期间暂时停止监听，未完成的下载、导出或分析任务需先结束。应用会在本地数据目录的 `backups` 下保留导入前的完整原始文件，校验或合并失败不会修改当前数据，提交过程出错会回滚。完成后仅恢复原先正在监听的任务，不自动监听新导入的主播。下载历史随包保留，已下载的 MP4 文件需自行复制；历史任务不会自动重新下载。

若手动备份数据目录，应先关闭应用，等待后台进程退出。SQLite 运行期间可能存在 `messages.sqlite3-wal`、`messages.sqlite3-shm`，不要在运行时只复制主数据库文件。

0.2.2 将旧 schema v1/v2 内容库事务迁移到 v3，保留原记录并增加场次分析表。旧版不能打开 v3；降级需使用升级前完整备份，不要手改数据库版本号。详见 [分析与升级边界](../engineering/SESSION_QUALITY_0.2.2.md)。

从 Windows「设置 → 应用」卸载。卸载保留用户数据目录；彻底清除前先完成备份，再手动删除该目录。

## 场次有效发言与更新

主播详情以剧集式卡片选择直播场次，默认显示六场；展开后按月份筛选和翻页，悬停或键盘聚焦卡片查看统计。日期显示为 26/10/25 格式。当前场次优先显示，零消息也登记。有效发言人数按账号 ID 去重，至少一条正常互动即可；未知 ID 不虚构人数。同人 60 秒同文至少 3 条、60 秒至少 20 条/10 人、整场至少 50 条/20 人会回溯排除对应组；保留原文和判定样本。阈值可按主播修改，已确认参与口令可按场填写，未核实时间保留待判定。有效发言统计继续使用本地规则，AI 互动亮点为下述独立功能。

历史和新增消息分批分析，统计中或需确认时有效率为「—」。可重新分析或暂停重算；分析导出与原始消息导出独立。监控有缺口时不补造内容，覆盖标为部分监控或覆盖未知。

设置默认「自动检查更新 · 每小时」，启动后检查，此后每小时检查，关闭后只手动检查。有更新可查看详细日志，点击暂停监控并更新并确认。下载或签名失败继续监控；验证通过才保存活动任务列表、暂停并落盘。更新后重新打开会恢复这些任务，手动停止的任务保持停止；同场次累计监控时长不含更新停机。安装启动失败尝试恢复当前任务。此能力从 0.2.2 开始提供，旧版发起本次升级仍按旧版流程。


## 在线人数刷新与场次在线指标

看板顶部「刷新人数」仅刷新正在监控的开播任务，沿用各自出口并显示进度；重复点击不创建新批次。场次悬浮统计展示最高在线、分钟均在线与有效发言／在线。均在线先对各分钟内实际采样求均值，再对已采样分钟等权平均；缺失分钟不补零，同场恢复继续。占比为整场去重有效发言人数除以均在线，可能超过 100%；无采样、分母为零或分析未完成显示「—」。场次分析导出在原 14 列后增加四列，原始聊天七列不变。详见 [0.2.4 更新说明](../../release-notes/0.2.4.md)。

## 直播互动回放与 AI 亮点

主播详情可播放社区生态已同步的录像，并按录像时间回放归档弹幕。先在「设置 → 社区生态」开启回放并保存 Key。无录像时黑框中央显示「暂无录播回放」。Windows 安装版使用原生播放器，优先 GPU 解码，设备不支持时回退软件解码。支持播放、暂停、拖动时间轴、音量和含弹幕全屏；控制栏空闲时自动隐藏。面积图仅统计有可靠平台时间的聊天消息，时间未知的聊天不编造位置。

红包和福袋以黄、粉两种半透明区间叠加在消息面积图上。有录像时面积图嵌入播放器进度条。密集重叠自动合并为颜色深浅受限的密度段；悬停查看轮次、重叠数量、奖品、参与条件及起止时间，点击定位对应活动开始。身份无法可靠确认的通知保留归档，不推测绘制区间。

活动开始优先使用明确的平台通知时间，缺少时按收到通知的观察时间定位并注明来源；已知的开奖、结束时间作为区间终点。未知时间不补造。观察时间不能证明平台实际发出活动的时刻。

在「设置 → 亮点分析模型」填写 API Key，默认服务地址为 https://llm-proxy.lilithgames.com/v1，也可改为自己的 OpenAI 兼容地址。点击「获取模型」读取上游实际模型列表，选定当前模型后保存；配置由所有主播共用，Key 在后台加密保存。

回到主播详情点击「分析本场」，会将本场全部可用归档、活动、在线采样和状态发送至所配置的服务，以单次 Prompt 分析互动亮点，可能产生该服务的调用费用。💡 标记可点击定位并查看聊天证据。配置未完成时不会开始分析，获取模型也不会自动触发场次分析。

输入超过单次限制或模型上下文不足时提示失败，不截断、分批或自动重试模型请求。分析只覆盖已监控归档，无法补采监控前或断线期间的数据，也不确认发言账号背后的自然人身份。

## 录像整场下载、切片与兼容性检查

录像同步后，可点击播放器下方的「下载整场」，无需框选时间或等待解码器成功播放。后台根据已结束 HLS 录像清单确认实际总时长，下载全部分片并原画封装成 MP4，不以已监控时长截短。整场与切片均在「录像下载」查看进度、取消、重试和打开文件夹，使用相同的文件夹与命名规则。仍在生成的录像需等待清单结束；暂不支持加密录像、独立音轨和 MP4 直链。整场上限为 31 天、64 GiB，切片原有 15 分钟限制保留。

录像加载后点击剪刀进入选区模式，拖动时间轴或调整起止时间，点击「下载 MP4」后按设置中的下载位置和命名规则创建任务。互动亮点可一键选取前 15 秒、后 30 秒片段，无需再次请求 AI。任务在后台运行，可在「录像下载」查看进度、取消、重试和打开已完成文件。当前最多选取 15 分钟，使用原画快速封装，实际边界依关键帧和媒体包时间为准，并在任务中显示。暂不支持加密录像、独立音轨及跨编码断点的片段。

「设置 → 诊断 → 兼容性检查」按需检查系统、GPU、驱动、WebView、浏览器编码能力与媒体组件。浏览器能力声明不能证明实际硬解已启动；报告中的原生播放器状态来自播放器实测。复制报告会隐藏密钥、媒体链接和用户路径。日常界面文字禁止选取，输入框、直播间/主播/场次 ID 和调试报告仍可选取复制。
